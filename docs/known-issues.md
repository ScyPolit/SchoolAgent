# 已知限制与下一步

用户已要求完整使用最新版 LibreChat 客户端，并于 2026-11-05 进一步授权更新既有 Docker 服务。当前实际前端基线为 `f4154b649efa37e1345ccc517a4d8d1ed2178c82`；原版共享包及完整客户端构建已执行。旧自制 UI 的截图与测试不能当作这个新前端的验收。既有单机 Docker 增量更新已验证，从零构建及学校完整环境仍待验收，见 [更新记录](docker-update.md)。

1. **Polymas 已有一个真实高级工作流上架样例，其余接口仍须分别验收。** 2026-11-05 已验证实际网关鉴权、普通 JSON 的 V2 路由、纯文本完成事件、登录用户追问和游客问答。传统助手接口的 AES 互通、其他应用授权与变量仍待各自核对；原普通 JSON 助手路由的 HTTP 500 不计为已解决。文档没有远程停止接口，固定使用本地停止提示。见 [上架流程](polymas-listing.md)和[接入指南](polymas-integration.md)。
2. **Dify 适配代码未对校内实例执行。** 需实际版本、应用类型、`/v1` 基地址、密钥、问题/历史输入与答案输出映射。Chatflow 每次以活动历史恢复新会话，避免远端旧分支污染，但具体应用对历史的理解效果仍须有真值的问题验证。Workflow 若没有历史变量会明确拒绝多轮。
3. **正式邮件投递仍待验收。** 邮箱继续作为登录账号，收信验证现由后台开关控制，默认关闭；关闭时未验证账号也可登录。开启后须完成验证，发送失败会如实提示。QQ SMTP 的发件人校验已支持名称加邮箱；本机已完成 `smtp.qq.com:465` 的 TLS 连接和欢迎响应检查，未使用真实授权码发信。管理员初始化和受控创建账号仍按可信预置标记已验证。Mailpit 只用于开发收件。
4. **最新完整客户端已有本地浏览器与性能证据。** 原版游客聊天、重新生成/版本切换、文字反馈 SQL 持久化、游客导出转登录、普通账号真实登录与明确确认迁移已通过界面操作；超管 12 个管理入口、首页欢迎语保存/重开回显及恢复、1 天固定分享正文、原生 MD 自定义文件名下载、390×844 管理页/长会话无整页横向溢出和原版 light 主题切换均有本轮记录。MD 下载文件 40,661 字节，哈希与 HTTP 导出相同；PDF/PNG 仍是 HTTP 实物证据。最终生产构建的公开分享日期正常且继续入口已隐藏，深色管理标题的桌面/手机截图可读性复验通过；最终三次全新浏览器冷启动已通过原版性能预算，数据见 performance-test-evidence.json；该结果不代表真实工作流响应速度。复制按钮可点击，但Chrome拒绝自动读取剪贴板，不能把它记为内容核验通过。原 PAGE_HUNG 失败保留，认证自等待修复不作为 renderer 无响应的唯一根因证明。当前在线客户端关闭不需要的自动 Service Worker 注册，决策见 [说明](online-client-service-worker.md)，最终构建绑定的具体界面范围见 [原生证据](native-ui-test-evidence.json)。不沿用旧界面证据，也不据此声称整项生产验收完成。
5. **网络边界必须在学校环境配置。** Docker 默认只发布回环地址；学校 HTTPS 入口应设置真实校内/VPN 来源范围。分享与验证/重置链接同样采用 `PUBLIC_URL`。微信是真机内置浏览器待验收，不以桌面模拟替代。
6. **真实上游容量未测。** SQLite 采用 WAL、单应用进程和异步上游连接；这是设计选择，不能换算为达到 20 路真实并发。后续使用真实上游、真实服务器测量并明确通过阈值。单个数据库不要放网络共享盘或同时挂给多个应用副本。
7. **取消受上游能力约束。** 请求取消成功不等于已核验停止；不能确认时保留 `unknown/failed/local_only` 状态及提示。断开/超时后远端可能继续执行，不自动重试。
8. **本地清理不会自动清理上游及离线备份。** 永久清理会清除本平台正文、回答版本、反馈及分享副本；保留的调用日志只有元数据。备份恢复可能使旧记录/分享重新出现，恢复后应先在隔离环境执行保留规则与撤销状态核对，再开放流量。
9. **超长导出采用分段。** PNG 超过 16000 像素自动返回有顺序编号的多图 ZIP；极大内容仍受渲染器内存限制，失败会明确返回错误，不提供被静默截断的成功文件。PDF/PNG 渲染资源忙碌返回可重试提示，和聊天业务配额无关。
10. **完整上游前端与学校后端存在契约差异。** 当前运行输入是完整 LibreChat 客户端，旧模块级复用源码退出入口；学校能力通过原版源码修改和 API 兼容层接入。原版文件、语音、模型和知识编辑等非本期入口需要按学校范围关闭，不能依赖另运行一套原版后端来掩盖缺失适配。
11. **上游开发依赖仍有低/中危审计项。** 根目录审计与上游工作区审计独立；高危 `follow-redirects` 已修复为兼容版 `1.16.2`，新上游审计为 0 高危、0 严重，仍有 10 低危和 42 中危报告，主要来自 ESLint/Jest/glob、构建与浏览器兼容依赖。保留实际报告 `artifacts/npm-audit-upstream.json`，后续随上游兼容修复更新，不用不兼容降级制造零漏洞数字。

本地三次冷启动和既有 Docker 增量更新检查已完成，各项浏览器操作与 API/实物测试的区别见测试报告。后续为从零构建、两平台/正式 SMTP 联调、真机网络检查和真实 20 路容量。所有失败与限制继续记录在逐项需求追踪表中。
