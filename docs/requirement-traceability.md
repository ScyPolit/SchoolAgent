# 需求追踪表

依据 [需求文档](requirements.md) 与用户后续要求：完整使用真实最新版 LibreChat 前端，只在上游源码上增删修改；交付使用 Docker，**当前不执行 Docker**。本地非 Docker 构建、测试已获后续授权并实际执行，早期“暂不测试”不再描述当前状态。

实际前端位于 `upstream/LibreChat/client`，固定 `v0.8.9-rc1` / `f4154b649efa37e1345ccc517a4d8d1ed2178c82`，共享包位于该仓库 `packages/{data-provider,client,chat}`。学校只运行一套 Node24/SQLite 身份和数据后端，通过 `/api/librechat` 兼容原版协议；旧自制 React19 页面在 `archive/`，不参与运行。许可、源码校验和变更清单见 [基线说明](librechat-latest.md)。

下表区分代码实现、本地证据和正式验收。本地协议夹具、测试 SMTP 和导出实物不能替代正式平台、正式邮件或学校网络验收。真实原版界面已实际完成游客聊天、重生成/版本切换、文字反馈、登录与明确确认迁移、1 天分享创建/正文、MD 自定义文件名下载、管理入口/首页保存、手机视口及原版 light 主题切换等检查；逐项范围见 [测试报告](test-report.md) 和与最终构建绑定的 [原生界面证据](native-ui-test-evidence.json)。最终生产构建的公开分享日期/只读入口、深色标题桌面/手机可读性复验已通过，三次全新浏览器冷启动性能已通过原版预算；复制按钮可点击但Chrome拒绝读取剪贴板，未作内容通过结论，PDF/PNG UI 下载未单独验收。原 `PAGE_HUNG` 失败保留；认证刷新自等待等已修复缺陷不作为 renderer 无响应的唯一根因证明。最终测试计数与浏览器结论见测试报告和 [验收清单](acceptance.md)，不将整项生产验收标为通过。
