# Polymas 智能体完整上架流程

适用：在 Polymas 维护智能体，在 SchoolAgent 提供校园入口。2026-11-05 已在既有 Docker 服务上完成一个高级编排电话查询应用的真实接入、上架、登录用户追问与游客问答。配置和测试均经授权，认证信息、真实业务记录与服务器入口不进入开源仓库。

## 1. 在 Polymas 确认发布信息

打开目标应用，核对名称、说明、知识库与工作流，进入“编辑 → 发布”。保留学校已确定的发布平台和访问权限，勾选“通过 API 使用”，再确定发布。

从发布页的“应用 id”读取 **appCode**。网关控制台中的 **APP ID** 用于获取令牌，不能填进 appCode。发布页的网页/移动端访问链接也不是 API 基础地址。

在发布页提供的权限控制台中核对网关应用及其“绑定应用”授权。已有有效网关凭据可以继续使用，无需重置 APPKEY。加密路由还需单独获取 paramkey；不要将 APPKEY 当作 paramkey。

## 2. 按实际接口配置接入

以有“平台接入”和“服务端凭据”权限的账号进入 SchoolAgent 管理后台，添加或编辑 Polymas 接入。

本次已验证的高级工作流配置如下，仅用于说明字段对应关系：

| SchoolAgent 字段 | 配置 |
| --- | --- |
| 正式 API 地址 | `https://openapi.polymas.com` |
| 智能体 appCode | Polymas 发布页的应用 id |
| 网关 appId / appKey | 权限控制台分配的网关凭据 |
| 已发布应用类型 | 工具工作流 V2，自定义输入输出 |
| 接口参数加密 | 本次实际路由使用普通 JSON；其他路由按平台要求选择 |
| 响应方式 | SSE，等待正式完成事件 |
| 问题输入变量 | `question`，与本次工作流开始节点一致 |
| 历史传递方式 | 将当前分支历史合并到问题 |
| 最终答案字段 | `text`，与本次工作流结束节点一致 |

这些是已验证应用的实际配置，不是所有 Polymas 应用的统一模板。传统聊天助手接口与独立工具的加密、输入输出、历史能力可能不同，详见 [协议接入指南](polymas-integration.md)。

高级工作流的 `OUT_COMPLETE.text` 可能直接是最终正文，也可能是包含业务字段的 JSON。选择 `text` 时兼容直接正文；选择 `main.text` 等字段时继续严格映射 JSON。中间 `ANSWER`、节点输出、资源对象和思考内容不会自动作为最终答案展示。

合并问题方式每次只附上本地当前分支历史，不复用上游旧会话。它需要实测模型是否理解追问，不等同于上游原生记忆。只有独立历史变量的工作流请选择“传入独立历史变量”；普通单次执行工具保留“仅单轮”。

## 3. 测试并上架

1. 保存接入，点击“实测连接与能力”，明确执行一次真实请求。
2. 检查调用日志，应为“已请求上游、已完成”；有文本不等于收到正式完成事件。
3. 到“智能体目录”绑定接入，填写名称、简介、分类和推荐问题。
4. 按学校范围配置用户组的可用智能体，避免直接授予所有智能体。
5. 启用“已上架”，按需勾选首页展示和推荐区。
6. 用目标身份进入智能体市场，从推荐问题开始真实对话；检查回答、追问、刷新后的历史和调用日志。

测试会消耗上游用量，不会后台自动重试。更换接入凭据时，空白密钥字段保留已保存值；不要把凭据放进说明、普通配置 JSON 或开源文档。
