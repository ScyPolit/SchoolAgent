## 4. Dify 已核实的公开能力

下表来自官方资料，不等于校内实例版本及其应用已经验证支持。

| 类型 | 官方能力边界 | 本项目处理 |
| --- | --- | --- |
| Workflow | 每次运行独立；通常通过 `POST /workflows/run` 调用 | 确认问题变量、历史输入和答案字段；没有历史接口时不能仅靠本地保存聊天实现多轮 |
| Chatflow | 支持会话上下文；通过 `POST /chat-messages`，后续延续 `conversation_id` | 保留用户/会话映射，验证追问与跨设备续聊 |
| 流式 | 两类接口支持事件流；事件与回答文字应区分 | 用已发布应用确认是否实际增量输出文本；否则用处理中加完整结果 |
| 停止 | 聊天和工作流有不同的停止接口，依赖任务标识 | 分类型调用；验证上游确实停止，不以 HTTP 成功响应代替实际终态验证 |
| 用户身份 | API 的 `user` 标识由接入方稳定提供 | 不采用用户可随意伪造的上游标识；迁移游客记录时明确远端身份策略 |
| 历史 | API 用户与网页用户的历史身份不自动相同 | 本平台管理自身新增历史，本期不承诺迁入原网页既有聊天 |

官方依据：[Workflow](https://docs.dify.ai/en/api-reference/guides/workflow)、[Chatflow](https://docs.dify.ai/en/api-reference/guides/chatflow)、[用户标识](https://docs.dify.ai/en/api-reference/guides/end-user-identity)。

### 4.1 普通 Workflow 的多轮实现选择

业务要求是用户可以接着上一问追问，具体技术路径在联调后确定：

1. 原工作流接受显式历史输入，本平台传入获准的同一会话上下文。
2. 原平台维护者把应用发布为具备会话能力的形式。
3. 使用原平台明确提供的其他正式会话机制。

本平台不擅自修改原工作流；需要改造时由原平台维护者完成或另行明确工作范围。若实际应用无法理解前文，该应用尚未满足多轮验收，不得仅因页面保留消息就标记完成。

### 4.2 流式判断注意事项

SSE 中可能包含节点开始、节点完成、心跳和最终结果。判定“回答真流式”需要看到结束之前多次到达的答案片段，不能只检查响应类型或是否出现进度事件。

也不能断言普通 Workflow 永远没有文本增量。官方工作流实现包含文本片段处理路径，实际行为需按实例版本和节点配置测试。[官方流式说明](https://docs.dify.ai/en/api-reference/guides/streaming)、[官方工作流实现](https://github.com/langgenius/dify/blob/main/api/core/app/apps/workflow/generate_task_pipeline.py)。

### 4.3 停止任务

- Chatflow：`POST /chat-messages/{task_id}/stop`。
- Workflow：`POST /workflows/tasks/{task_id}/stop`。
- 本平台统一保持原始用户身份。当前官方文档明确 Chatflow 必须匹配原 `user`（不匹配仍可能返回成功）；Workflow 的取消接口不检查该身份是否匹配。本平台始终先验证本地回答归属，不能仅凭外部任务标识发起取消。本地停止、取消已请求、实际停止分别记录。
- 停止接口和参数以校内实例对应版本为准。

官方依据：[停止聊天](https://docs.dify.ai/en/api-reference/chat-messages/stop-chat-message-generation)、[停止工作流](https://docs.dify.ai/en/api-reference/workflow-runs/stop-workflow-task)。

## 6. 上线前准备

- 至少一个真实 Polymas 和一个校内 Dify 应用完成上述验证，并确定首批智能体清单。
- 邮件提供方落实；验证注册、验证邮件重发、找回密码和邮件链接在校内/VPN 的可达性。
- 学校提供实际服务器、网络访问规则、站点域名及 HTTPS 条件；反向代理关闭影响流式的缓存行为。
- 在真实环境执行 20 路同时聊天，记录延迟和成功率，形成明确性能通过阈值。
- 固定开源基线版本；验证游客、权限、分享、导出和学校品牌配置的差异项。
- 确定备份、恢复、保留清理执行时点和维护责任；准备非敏感业务验收样例。

这些是现阶段的上线待办，不要求需求提出者现在提供全部技术信息，也不意味着可以跳过正式接入验收。
