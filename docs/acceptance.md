# 交付验收与外部依赖

此表区分实现路径、本地证据和学校真实环境验收。只有实际执行并记录的项目才能标记通过；开发模拟器不代表两家正式平台、正式 SMTP、学校网络或真实容量已通过。

## 验收映射

| 需求 | 实现路径 | 当前验收边界 |
| --- | --- | --- |

| V-03/V-04 邮件认证 | 邮箱验证、一次性找回令牌、SMTP 配置/测试 | 本地实际 SMTP 传输夹具已验证收信、拒收和鉴权失败；真实发件服务和网络可达性待校方 |
| V-05/V-06 两个平台及多轮 | Dify Chatflow/Workflow 适配；Polymas 网关/助手/工具 V2 适配 | 一个 Polymas 高级工作流的鉴权、V2 问答与两轮追问已实测；其他应用、AES 助手路由与校内 Dify 仍待验收 |

## 正式上线前必须补齐

- 一个 Polymas 高级编排应用已通过网关鉴权、V2 问答和追问；其他应用仍需逐项核对凭据、appCode、变量及业务真值，AES 路由还须验证 paramkey 加密互通。
- 校内 Dify 的实际版本、Chatflow/Workflow 应用模式、发布地址、输入输出映射、正式凭据和可验证的业务问答真值。
- SMTP 发件账号、学校 HTTPS 域名与证书、校内/VPN 来源范围、邮件及分享链接网络可达性。
- 真机微信/手机测试，两个平台分别验证多轮、停止、版本切换和游客迁移后的上下文。
- 真实 20 路同时聊天；记录开始/首段/结束延迟、成功/失败/停止、真实上游限流，并确认可接受阈值。
- 指定备份负责人、备份保管位置、恢复演练和数据清理授权，替换学校品牌与服务联系信息。

具体执行命令、通过数量、截图及导出文件应记录在最终验证报告中，不能仅根据代码存在把这些外部条件勾选通过。
