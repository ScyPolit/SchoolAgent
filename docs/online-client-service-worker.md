# 一期在线客户端与 Service Worker

一期使用学校在线API完成身份、权限、聊天和导出，不要求离线PWA。完整LibreChat客户端及原版UI继续保留；仅在原版 `upstream/LibreChat/client/vite.config.ts` 将 `VitePWA.injectRegister` 从 `auto` 改为 `false`，停止自动注入注册脚本。没有替换界面，也没有放宽性能预算。

## 决策依据与证据边界

最终生产构建的全新浏览器中，两次启用原版注册的检查均在初次目录快照成功后，后续点击/快照出现约60秒无响应。诊断中只拦截 `registerSW.js` 的新会话可连续操作聊天/历史超过30秒，但脚本拦截也触发过一次资产恢复重载；只拦截 `sw.js` 的新会话仍出现无响应。

这些对照支持关闭本期不需要的自动注册以缩小运行路径，**没有证明具体Chrome缺陷或唯一根因**。诊断拦截不属于正式通过证据。首次原版Lighthouse `PAGE_HUNG` 报告继续保留在 `artifacts/performance-campus/`；系统内存压力也曾存在，不能忽略这一潜在干扰。

## 运行边界与后续验证

- PWA插件仍可生成manifest和worker文件，但本应用不自动注册worker；不会把离线能力列为已交付功能。
- 之前在同源测试中安装的worker不会因修改HTML自动消失。验证使用全新浏览器配置；旧测试配置需通过浏览器开发工具注销该源worker后再比较，不在产品代码中清空用户全部浏览数据。
- 验证必须在没有拦截/故障注入的全新浏览器中完成，包括连续页面操作、认证和三次Lighthouse冷启动。结果见 [测试报告](test-report.md)，失败报告不能被后续重跑覆盖。
- Docker仍未执行；这次决策及本机结果不代表学校服务器、微信真机或正式平台已验收。
