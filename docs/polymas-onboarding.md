# Polymas 同类智能体上架说明

这份教程适用于：在 Polymas 使用高级工作流编排、以问题文本作为输入、以最终正文作为输出的对话智能体，例如校园电话查询、办事咨询和知识库问答。

完整流程：**Polymas 发布 → SchoolAgent 新建接入 → 实测连接 → 目录上架 → 用户组授权 → 前端验收**。新增智能体时请新建接入，不要覆盖已经在用的其他智能体配置。

## 一、上架前准备

你需要具备目标 Polymas 应用的管理权限，以及 SchoolAgent 的“平台接入”“服务端凭据”“智能体目录”“用户组与访问”权限。

先在 Polymas 核对三项内容：

1. **开始节点**：用户问题的输入变量名，例如 `question`。
2. **结束节点**：向用户展示的最终答案，例如 `text`。不要选择分类结果、检索原文或思考内容。
3. **应用效果**：在 Polymas 预览中确认知识库可用，实际问题能得到合理答案。

准备以下标识和凭据，三者不可混用：

| 名称 | 从哪里获取 | 填到哪里 |
| --- | --- | --- |
| 应用 appCode | 目标应用发布页，“通过 API 使用”下的“应用 id” | 智能体 appCode |
| 网关 appId | 权限控制台 → 应用管理 → 目标网关应用详情 → APP ID | 网关 appId |
| 网关 appKey | 同一个网关应用的 APPKEY | 网关 appKey |
| 参数加密 paramkey | 仅在对应接口要求加密时，向 Polymas 管理员获取 | 启用 AES 后的参数加密密钥 |

**不要把网关 appId、网页登录账号或其他应用的 ID 填进 appCode。** appKey 和 paramkey 也不是同一把密钥。

## 二、发布 Polymas 应用

1. 打开目标智能体，检查名称、介绍、知识库和工作流。
2. 进入“编辑 → 发布”。
3. 按学校要求确认发布平台和访问范围，启用“通过 API 使用”。
4. 记录该页显示的“应用 id”，然后点击“确定发布”。
5. 通过发布页的权限控制台入口，核对网关应用已经取得相关 API 授权。

后续改动了 Polymas 工作流或知识库配置时，要检查是否需要重新发布才能让 API 使用新版本。网页分享地址、移动端地址用于访问网页，不是 API 基础地址。

## 三、在 SchoolAgent 新建平台接入

打开“校园管理控制台 → 平台接入 → 新建”。同类型高级对话工作流可按下面的方式填写，但变量名和加密方式必须以目标应用为准。

| 后台字段 | 同类型应用的填写方法 |
| --- | --- |
| 名称 / 称呼 | 易辨认的接入名称，例如“校园问答 · Polymas” |
| 平台类型 | Polymas · 智能助手 / 工具工作流 |
| 已发布应用类型 | **工具工作流 V2 · 自定义输入输出** |
| 正式 API 地址 | `https://openapi.polymas.com`；学校有专属网关则使用实际地址 |
| 智能体 appCode | 第二步目标应用发布页的“应用 id” |
| 网关 appId、appKey | 同一网关应用的配套凭据 |
| 接口参数加密 | 已验证的同类 V2 路由使用**不加密 · 普通 JSON**；其他路由按平台要求设置 |
| 响应方式 | **SSE · 等待正式完成事件** |
| 问题输入变量 | 选择实际输入变量，例如 `question`；没有对应选项时选“自定义变量名” |
| 最终答案字段 | 直接输出正文的同类应用选择 **`text`** |
| 正文展示方式 | 确认 `ANSWER.text` 为最终答复模型的公开正文后，选择**实时正文 · 增量片段** |

基础地址只填写网关地址，不要追加 `/bot/v2/tool`，系统会按应用类型拼接接口。访问令牌由服务端自动获取和缓存，不用手动填写 token。已有接入的密钥框留空表示保留原值。

### 历史传递方式怎么选

| 你的工作流 | 应选择的方式 |
| --- | --- |
| 对话工作流只接收问题文本，希望支持追问 | **将当前分支历史合并到问题** |
| 开始节点明确提供独立历史变量，并且下游节点会使用它 | **传入独立历史变量**，再选择真实变量名 |
| 单次处理工具，不需要上下文 | **未配置 · 仅单轮** |

不要随便填一个 `history` 来假装支持多轮：上游工作流必须实际接收并理解历史。合并到问题时，系统只携带当前选定分支的消息；仍需要用真实追问检查应用效果。

### 最终答案字段怎么选

- 结束事件直接返回最终正文：选择 `text`。
- 最终输出是 JSON，例如 `{"answer":"正文"}`：选择 `answer`。
- 最终输出是嵌套 JSON，例如 `{"main":{"text":"正文"}}`：选“自定义变量名”，填写 `main.text`。

这里配置的是**给用户看的主答案**。系统仍以正式完成事件确认本次调用结束。

### 如何启用真实流式正文

先选择 SSE 响应和 `text` 最终答案字段，再选择“实时正文 · 增量片段”。接口按累计全文推送时，改选“累计全文”；不能确认片段语义时保留“仅最终答案”。

系统会立即显示首个真实正文片段，对密集片段做短时合并以减少页面重绘，最终用 `OUT_COMPLETE` 中的主答案核对和校正。连接、处理和生成阶段会显示等待状态与已用时间；不会把已经完整返回的答案人为拆字来伪装上游流式。

工作流的分类、检索和模型准备本身仍可能耗时。前端流式不会让上游计算提前完成；如果迟迟没有正文片段，应在 Polymas 检查工作流节点耗时、知识检索及模型设置。

## 四、保存并执行一次真实测试

1. 保存平台接入。
2. 点击该接入右侧“实测连接与能力”。
3. 选择一个简单测试问题，点击“执行测试”。
4. 确认测试成功，再到“调用日志”查看对应记录。

成功记录应显示“已请求上游、已完成”。测试会调用真实 Polymas 应用，可能计入平台用量；打开说明文档不会发起调用。

调用日志会分别显示“首段正文”和总耗时。启用真实流式后，首段时间通常早于总耗时；如果两者接近，说明应用可能只在末尾给出正文，或大部分时间花在上游前置节点。

一次连接成功不等于知识答案、追问、分支恢复和停止都已验收。不要连续反复点击测试来掩盖报错。

## 五、在智能体目录上架

打开“智能体目录 → 新建”，填写：

| 字段 | 建议 |
| --- | --- |
| 名称 / 称呼 | 用户看得懂的名称，例如“校园电话查询助手” |
| 头像图片地址 / 表情 | 合适的图片地址或表情 |
| 简介 | 说明能做什么、覆盖范围和资料来源 |
| 分类 | 例如“校园服务” |
| 平台接入 | 选择刚刚测试通过的接入，注意同名项目 |
| 推荐问题 | 每行一个真实可回答的问题，建议先提供 2～3 个 |
| 首页展示 | 勾选后才会出现在对应的市场/首页入口 |
| 推荐区 | 按需勾选 |
| 已上架 | 验证配置后勾选并保存 |

推荐问题示例：

- 我是本科生，想咨询学籍业务。
- 我想办理校园卡，应该联系哪个部门？
- 宿舍设施需要维修，应该联系哪里？

请根据自己的知识库替换示例，不要让推荐问题超出应用实际能力。

## 六、配置谁能看到和使用

打开“用户组与访问”，编辑目标用户组，在可用智能体中勾选刚上架的智能体并保存。

- 面向游客开放：配置“游客默认组”。
- 面向普通登录用户开放：配置“注册用户默认组”或实际业务组。
- 仅供指定部门：只配置该部门对应的组。

**上架、首页展示和用户组授权需要同时满足。** 只勾选“已上架”，不代表每个人都能在市场中看到；也不必为了开放一个应用而勾选“全部”。

## 七、从用户入口完成验收

用目标身份进入“智能体市场”，检查以下流程：

1. 能看到正确的卡片、简介和推荐问题。
2. 点击推荐问题，进入对话后发送，获得真实回答。
3. 追加一个依赖上文的追问，例如“那如果是研究生办理同类业务呢？”。
4. 刷新页面，确认问题和回答恢复。
5. 核对调用日志，确认真实上游调用及最终状态。
6. 如果开放游客入口，再用独立游客会话重复检查。

知识库负责人还应核对部门职责、电话号码、办理依据等业务内容。系统调用成功不代表每一条知识都已经核实。

## 常见问题与排查

| 现象 / 错误 | 优先检查 |
| --- | --- |
| `UPSTREAM_HTTP_500` | appCode 是否来自目标发布页、接口类型是否适合应用、参数加密是否与该路由一致；仍失败需核对平台侧日志 |
| `POLYMAS_40000` | 网关应用所属组织是否已取得该 API 的授权 |
| `POLYMAS_CREDENTIALS_REQUIRED` | 网关 appId 和 appKey 是否完整保存 |
| `POLYMAS_PARAM_KEY_REQUIRED` | 当前选择了 AES；应补齐真正的 paramkey，或确认该路由是否实际使用普通 JSON |
| `ANSWER_MAPPING` | 最终输出是纯文本还是 JSON；字段名是否应为 `text`、`answer` 或嵌套路径 |
| `POLYMAS_HISTORY_REQUIRED` | 接入仍为“仅单轮”；应按工作流能力配置历史方式 |
| `UPSTREAM_INCOMPLETE` | 上游没有返回正式完成事件；检查应用发布状态、网关连接和平台执行记录 |
| 后台已上架，市场却看不到 | 检查首页展示、目标用户组授权，以及当前登录身份 |
| 更新工作流后效果没变化 | 确认改的是目标应用，并核对是否已经重新发布 |

普通配置先保留高级设置默认值。只有平台管理员明确要求时，才修改 Authorization 前缀、网关相对路径或 AES 密钥编码。

Polymas 文档没有提供远端停止接口：停止本地接收后，上游可能继续执行。密钥只录入后台凭据字段，不要写进简介、普通 JSON、截图或开源仓库。
