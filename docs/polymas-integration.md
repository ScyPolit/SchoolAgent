# Polymas 接入指南

2026-11-05 已在用户授权登录后读取官方文档，并实现对应服务端适配器。协议测试和本地 HTTP 夹具通过不代表学校发布应用已经验收；真实网关凭据、应用变量与业务答案仍需管理员核对。浏览器研究和本地界面测试使用独立后台会话，不操作用户前台。

## 选择正确的接口

官方[智能助手文档](https://platform.polymas.com/instructions?docNid=KIGeJe725k&childIndex=1)同时包含聊天和工具工作流，后台提供两种选择：

| 已发布应用 | 后台选择 | 默认接口 | 请求与答案 |
| --- | --- | --- | --- |
| 智能助手 | 智能助手 · 聊天 SSE 接口 | `POST /bot/t/v1/completions/chat/stream` | `question/appCode/userNid`；以 `end: true` 的 `context.answer` 为最终答案 |
| 自定义工具工作流 | 工具工作流 V2 | `POST /bot/v2/tool` | `appCode/userNid/stream/flowData`；阻塞响应读取 `data`，SSE 在 `OUT_COMPLETE` 解析 `text` 内的 JSON，再提取配置的主答案字段 |

工作流的 `ANSWER` 和节点事件可能是内部中间结果，默认不作为正文输出。工具工作流因此可能在完成后一次显示答案；系统不会把完整答案拆成字符假装上游增量。助手也默认只展示最终答案，只有对实际应用确认 `message` 是增量或累计文本后，才在高级设置启用对应处理方式。

## 准备三个不同的标识或凭据

| 后台字段 | 来源和用途 | 保存方式 |
| --- | --- | --- |
| 智能体 appCode | 已发布智能体的“通过 API 使用”入口；标识业务应用 | 普通接入元数据 |
| 网关 appId | 网关管理员分配；用于获取访问令牌，与 appCode 不同 | 服务端加密凭据 |
| 网关 appKey | 与网关 appId 配对的签名密钥 | 服务端加密凭据 |
| 参数加密 paramkey | 使用参数加密的路由需要向平台管理员索取 | 服务端加密凭据 |

密钥只在本项目管理后台录入。页面不会回显已保存值；留空表示保留，支持单独更新某个凭据。在高级设置勾选清除凭据会整体移除；更换平台类型也会清除原平台凭据，避免串用。`config` 中禁止存储已知密钥字段。

正式网关和令牌规则依据官方[网关接入文档](https://platform.polymas.com/instructions?docNid=UvtFSkcFIR&childIndex=2)：

- 默认基础地址为 `https://openapi.polymas.com`。
- 服务端请求 `GET /api/token`，附上 `appId`、毫秒 `timestamp` 与 `MD5(appId + appKey + timestamp)` 小写签名。
- 按返回的 `expires_in` 缓存令牌，提前留出到期余量，同一凭据的并发获取合并为一次请求；修改凭据会使用不同缓存。
- 默认把访问令牌原文放入 `Authorization`。文档没有提供完整 SDK/cURL 来进一步证实前缀；兼容网关若明确要求 Bearer，可在高级设置选择，不能据此声称真实鉴权已通过。
- HTTP 401 或业务码 40001 会使缓存失效；业务 POST 不自动重试，避免重复执行。40000、40002、40004–40007 转成明确且不包含上游原文的错误提示。

## 配置步骤

1. 以具有“平台接入”和“服务端凭据”权限的账号进入 **管理后台 → 平台接入 → 添加**。
2. 选择 Polymas，再选择已发布应用的类型；不要用网页分享链接代替 API 地址。
3. 分别填写 appCode、网关 appId 和 appKey。已有接入的空白密钥字段会保留原值。
4. 核对参数是否加密。助手默认 AES，工具工作流默认普通 JSON；具体以网关路由的“参数是否加密”设置为准。启用 AES 时填写 paramkey。
5. 工具工作流选择问题变量、历史变量和最终答案字段。快捷选项只是常见名称，必须与应用定义一致；其他名称选择“自定义”。嵌套答案可填写 `main.text`。没有历史变量的工具只能单轮使用，后续追问会明确拒绝。
6. 保存后进入“测试”，选择测试问题并点击“执行测试”。这会发送一条真实请求，可能计入 Polymas 用量；不会自动执行或自动重试。
7. 分别验证真实答案、多轮追问、切换旧回答后再追问、停止和调用日志。通过后再在智能体目录绑定、上架并授权用户组。

普通配置不需要编写整体 JSON。高级设置保留固定业务输入、网关相对路由、Authorization 格式与 AES 兼容选项；其他原有高级配置在编辑保存时保留。

## 加密的互通边界

官方说明约定 AES ECB、ZeroPadding，并将 paramkey 的小写 32 位 MD5 用作密钥；未提供可以核验的 SDK 或包含 paramkey 的公开测试向量。实现默认将这 32 个字符按 UTF-8 编码为 AES-256 密钥，JSON 按 UTF-8 编码并用零字节补齐到块边界，然后 Base64 编码放入 `secretParam`。

后台另提供 MD5 摘要字节（AES-128）兼容选项。该选项不是已经核实的平台要求，仅用于平台管理员确认另一种编码时适配；两种编码都有本地加解密契约测试，但真实互通仍必须用正式网关验证。不会使用网页登录 Cookie 代替正式 API 凭据。

## 历史、分支与停止

助手每次省略 `sessionNid/chatNid`，将本地当前选定分支历史附入新问题，避免远端旧分支混入；这是一种本平台的历史恢复策略，应用是否正确理解需要真实业务样例验证。工具工作流把历史 JSON 映射到管理员选择的变量。上游返回的 `sessionNid/chatNid` 仅作追踪记录；稳定的匿名 `userNid` 不使用学校账号邮箱。

正式文档没有远程停止接口，因此取消固定报告 `local_only`：停止本地接收，上游可能继续执行。不会构造不存在的停止请求，也不会把断线、EOF、`[DONE]` 或内部节点结束当作业务成功。助手要求明确的 `end: true`，工具要求 `OUT_COMPLETE`；缺失语义终态记为未确认，并保留已接收的部分内容。

本地删除、保留任务与用户退出均不代表删除 Polymas 远端记录。助手高级设置可关闭 `saveHistoryFlag`，但实际留存规则仍需平台管理员确认。

## 本地验证范围

`tests/polymas.test.js` 覆盖签名、令牌缓存/并发合并、参数加密、活动历史、答案映射、UTF-8 SSE、正式终态、业务错误、取消与禁止自动重试；`tests/polymas-chat.test.js` 使用真实校园 Cookie、管理 API 和本机 HTTP 模拟网关，验证凭据加密、两个接口、历史映射、回答与调用日志落库。`tests/admin.test.js` 验证独立权限、凭据不回显和部分更新。

这些测试不向 Polymas 发送业务请求，不会生成学校业务调用量，也不能替代学校应用、网关授权、实际变量和业务真值的验收。Docker 本轮未执行。
